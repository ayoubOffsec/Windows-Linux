# Linux Logging for SOC

## Overview

Linux Logging is the process of recording system activities, authentication events, application behavior, and security-related events.

Linux logs help system administrators and SOC analysts monitor system activity, investigate incidents, identify suspicious behavior, and understand what happened on a Linux machine.

This document provides a practical reference for locating, reading, and analyzing Linux logs during security investigations.

## 1. Linux Log Locations

Most Linux distributions store system logs in:

```bash
/var/log/
```

This directory contains log files generated by the operating system, services, authentication mechanisms, and applications.

To list available log files:

```bash
ls -lah /var/log/
```

---

## 2. Important Linux Log Files

Log file names and locations may vary depending on the Linux distribution and logging configuration.

| Log File | Description |
|---|---|
| `/var/log/syslog` | General system activity and messages (Debian/Ubuntu). |
| `/var/log/messages` | General system messages (RHEL-based distributions). |
| `/var/log/auth.log` | Authentication and authorization events (Debian/Ubuntu). |
| `/var/log/secure` | Authentication and security events (RHEL-based distributions). |
| `/var/log/kern.log` | Kernel-related messages. |
| `/var/log/dmesg` | Kernel ring buffer messages captured during boot and hardware initialization. |
| `/var/log/boot.log` | System boot messages. |
| `/var/log/cron` | Scheduled task activity (commonly on RHEL-based systems). |
| `/var/log/audit/audit.log` | Security audit events when auditd is configured. |

**Important:** Not every Linux distribution uses all these files. Some systems rely primarily on systemd-journald instead of traditional text-based logs.

## 3. System Logging Services

Linux commonly uses two main logging components.

### 3.1 rsyslog

`rsyslog` is a logging service that collects, processes, and stores system messages.

It can record events from:
- System services.
- Applications.
- Kernel messages.
- Authentication services.

Check its status:

```bash
systemctl status rsyslog
```

### 3.2 systemd-journald

`systemd-journald` collects and manages system logs in systems using systemd.

Unlike traditional text-based logs, journal entries are stored in a structured format.

View all available journal entries:

```bash
journalctl
```

View logs from the current boot:

```bash
journalctl -b
```

View recent entries:

```bash
journalctl -n 50
```

Follow new log entries in real time:

```bash
journalctl -f
```

## 4. Viewing and Searching Logs

Linux provides several command-line tools for analyzing log files.

### 4.1 cat

Display the entire contents of a file:

```bash
cat /var/log/auth.log
```

### 4.2 less

Read large log files page by page:

```bash
less /var/log/auth.log
```

### 4.3 tail

Display the last 20 lines:

```bash
tail -n 20 /var/log/syslog
```

Monitor new log entries in real time:

```bash
tail -f /var/log/auth.log
```

### 4.4 grep

Search for specific keywords:

```bash
grep "Failed password" /var/log/auth.log
```

Search without case sensitivity:

```bash
grep -i "error" /var/log/syslog
```

### 4.5 journalctl

Filter journal entries by service:

```bash
journalctl -u ssh
```

Filter logs by time:

```bash
journalctl --since "1 hour ago"
```

View only error-level messages:

```bash
journalctl -p err
```

## 5. Authentication Log Analysis

Authentication logs are particularly important during SOC investigations.

They record activities related to user authentication, SSH connections, and privilege escalation.

### Common SSH Log Messages

| Log Message | Meaning |
|---|---|
| `Failed password` | Failed authentication attempt. |
| `Accepted password` | Successful password authentication. |
| `Accepted publickey` | Successful public key authentication. |
| `Invalid user` | Login attempt using a nonexistent username. |
| `session opened` | A user session was opened. |
| `session closed` | A user session was closed. |
| `sudo` | Records sudo-related activity, depending on configuration. |

### Important Commands

Find failed SSH login attempts:

```bash
grep "Failed password" /var/log/auth.log
```

Find successful SSH logins:

```bash
grep "Accepted" /var/log/auth.log
```

Find invalid usernames:

```bash
grep "Invalid user" /var/log/auth.log
```

**Note:** On RHEL-based systems, authentication logs are commonly stored in `/var/log/secure` instead of `/var/log/auth.log`.

## 6. Important Log Investigation Commands

### 6.1 Check Login History

```bash
last
```

Displays information about previous login sessions using the system's login records.

### 6.2 Check Failed Login Attempts

```bash
lastb
```

Displays recorded failed login attempts, usually from `/var/log/btmp`.

### 6.3 Check Current Logged-in Users

```bash
who
```

Displays users currently logged into the system.

### 6.4 Check User Activity

```bash
w
```

Displays logged-in users and their current activity.

### 6.5 Check Sudo Activity

```bash
grep "sudo" /var/log/auth.log
```

Displays matching sudo-related authentication log entries.

### 6.6 Check System Services

```bash
systemctl --failed
```

Lists services that have failed.

## 7. Common Security Investigations

### 7.1 Detecting SSH Brute-Force Attempts

**Log Source:** `/var/log/auth.log` or `/var/log/secure`

Investigation steps:

1. Search for `Failed password`.
2. Identify the targeted usernames.
3. Examine source IP addresses.
4. Compare timestamps.
5. Look for repeated attempts from the same source.

Repeated failed attempts may indicate brute-force activity.

### 7.2 Investigating Successful SSH Logins

**Log Source:** Authentication logs.

Check:

- Username.
- Source IP address.
- Login timestamp.
- Authentication method.
- Whether the login was expected.

An unfamiliar successful login may require further investigation, especially if preceded by repeated failed attempts.

### 7.3 Investigating Privilege Escalation

**Log Source:** Authentication logs and audit logs.

Look for:

- Sudo commands.
- Changes in user privileges.
- Unexpected administrative activity.
- Unusual access to privileged accounts.

### 7.4 Investigating Suspicious Services

**Log Source:** System journal and service logs.

Useful commands:

```bash
systemctl --type=service --state=running
```

```bash
journalctl -u service_name
```

Investigate unfamiliar services, unexpected execution, or unusual service failures.

### 7.5 Investigating System Errors

**Log Source:** `/var/log/syslog`, `/var/log/messages`, or systemd journal.

Search for errors:

```bash
journalctl -p err
```

Review repeated errors, unexpected shutdowns, and unusual system behavior.

## 8. Basic Investigation Workflow

A simple workflow for investigating Linux activity:

1. **Identify:** Determine what activity needs investigation.
2. **Locate:** Find the relevant log file or journal source.
3. **Filter:** Search for relevant keywords, timestamps, or users.
4. **Inspect:** Examine IP addresses, usernames, and event details.
5. **Correlate:** Compare related events to build a timeline.
6. **Evaluate:** Determine whether the activity is normal or suspicious.
7. **Document:** Record findings and relevant timestamps.

---

## 9. Important Analysis Principles

- A single failed login does not necessarily indicate an attack.
- Always examine the context surrounding an event.
- Correlate failed and successful authentication attempts.
- Check source IP addresses and usernames.
- Investigate unexpected sudo activity and privileged access.
- Remember that log locations differ between Linux distributions.
- Missing logs do not necessarily mean an activity never occurred.
- Log retention and permissions can affect investigation results.

## Conclusion

Linux logs provide valuable information about authentication, system activity, services, and security-related events.

Understanding how to locate, filter, and correlate these logs helps administrators and SOC analysts investigate suspicious behavior, detect unauthorized access, and reconstruct activities performed on a Linux system.

This knowledge is useful for Linux administration, troubleshooting, and basic security monitoring.
